# F034.3 — Explicit opt-out from the default cost-sink

## Motivation

F034 (v0.24.0) made cost-tracking the default: a bare `createAI()` auto-wires the
upmetrics sink whenever `UPMETRICS_API_KEY` is in the env. That is right for the
~91% of call-sites that reported nothing. It is **wrong** for a consumer that
already reports its own costs — for them the auto-wire silently ADDS a second
reporting path, and every call is counted twice in production.

Reported by **buddy** (announcement #18883), measured in their repo:
`apps/server/src/ai-complete.ts:55` calls `createAI({})` deliberately without a
sink. The comment three lines above states the intent verbatim:

> "No cost sink here — cost is recorded to cli_usage below, which the hourly
> Upmetrics push already aggregates (avoids a second, double-counting push)."

They record every call to `cli_usage` and push an hourly aggregate. If they bump
to 0.24.0 with the key in `.env`, their AI spend **doubles in the numbers** — in
production, with no error anywhere. They need the key present for their own push,
so "remove the key" is not an escape.

**Verified 2026-08-06: there is no opt-out today.** Probed all three candidates
against the real client with the key set — `costSink: null` → 1 POST, explicit
`costSink: undefined` → 1 POST, `UPMETRICS_AUTOWIRE=0` → 1 POST. The presence of
the key is the only signal, so a self-reporting consumer cannot escape. This
blocks buddy's bump.

Same class as the test-telemetry trap (F034.1): auto-wiring without consent. The
other direction — not fabricated usage from tests, but real usage double-counted
from a consumer that already reports.

## Scope

Extend "explicit wins" to "explicit none": `createAI({ costSink: null })` means
*no sink, do not auto-wire*. Precise, per-instance, and self-documenting at the
call-site where the "we already report" comment lives.

- `AiConfig.costSink?: CostSink | null` (schema `.nullable()`).
- Resolution: `undefined` → auto-wire from env (unchanged); `null` → no sink;
  an explicit sink → use it (unchanged).

### Non-goals

- **No `UPMETRICS_AUTOWIRE=0` env flag.** A process-wide switch is invisible at
  the call-site and would also silence `createAI()` instances that *should*
  track. Offered to buddy on request; the per-instance form fits their case.
- No change to the default. Cost-tracking stays on by default — the €53
  invisible-spend problem is why F034 exists.

## Reuse

Checked before building: this is the internal resolution logic of
`@broberg/ai-sdk`'s own `createAI()`. No shared `@broberg/*` package owns
cost-sink wiring — this repo IS the fleet's AI/cost primitive. Nothing to reuse,
nothing to extend elsewhere.

## Rollout

Additive and backward-compatible — no existing call-site changes behaviour.
Patch release; buddy then bumps and sets `costSink: null` at `ai-complete.ts:55`.
Buddy is protected in the meantime by their version lock (`^0.21.1` cannot reach
0.24.0, since caret locks minor on 0.x).
